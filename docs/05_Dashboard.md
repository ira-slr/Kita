# CHAPTER 5: DASHBOARD

The Dashboard is the operational nerve center of SariSmart. It is the first screen the user sees upon launching the app post-onboarding. Its primary objective is to provide a comprehensive, at-a-glance overview of the business's health and provide immediate access to the most frequent actions.

## 5.1 General Layout & Navigation
*   **Architecture:** The Dashboard utilizes a ScrollView to accommodate various widgets on smaller screens.
*   **Top App Bar:** 
    *   Left side: Store Name (e.g., "Aling Nena's Sari-Sari").
    *   Right side: User Profile Icon (links to Settings) and a Notification Bell icon (with a red dot if unread alerts exist).
*   **Bottom Navigation Bar:** Fixed at the bottom of the screen across the main application views. It contains four icons:
    *   Dashboard (Home icon, currently active)
    *   Inventory (Box icon)
    *   POS (Cash register icon)
    *   Reports (Chart icon)

## 5.2 Widget 1: The Financial Summary Card (Hero Widget)
*   **Position:** Top of the Dashboard, immediately below the App Bar.
*   **Visuals:** A large, brightly colored card (using a gradient of the primary brand colors).
*   **Content:**
    *   **Daily Sales:** Prominently displayed in large, bold typography (e.g., "₱ 1,450.00").
    *   **Subtitle:** "Total Sales Today".
    *   **Profit Indicator (Optional toggle in settings):** A smaller text below sales showing estimated profit: "Est. Profit: ₱ 320.00".
    *   **Trend Arrow:** A small green arrow pointing up (or red down) comparing today's sales at this exact hour to yesterday's sales at the same hour.
*   **Interaction:** Tapping this card routes the user directly to the "Daily Report" view in the Reports module.
*   **Database Query:** The system executes a `SUM(total_amount)` query on the `transactions` table where the timestamp is within the current calendar day.

## 5.3 Widget 2: Quick Actions Grid
*   **Position:** Below the Financial Summary Card.
*   **Visuals:** A 2x2 or 1x3 grid of large, touch-friendly circular buttons with recognizable icons.
*   **Buttons:**
    1.  **Scan Receipt:** Icon of a camera/receipt. Primary color. Routes directly to the OCR camera module.
    2.  **Add Product:** Icon of a plus sign on a box. Routes to the manual "Add Inventory" form.
    3.  **New Sale (POS):** Icon of a shopping cart. Routes to the Point of Sale screen. (This is redundant with the bottom nav but provided for immediate central access).
*   **Interaction:** Tapping any button triggers a ripple effect and instantly routes the user to the respective module.

## 5.4 Widget 3: Low Stock Alerts
*   **Position:** Below the Quick Actions Grid.
*   **Visuals:** A horizontally scrolling list (carousel) of warning cards, or a condensed list view if vertical. The header reads "⚠️ Low Stock Alerts".
*   **Content per Card:**
    *   Product Image (Thumbnail)
    *   Product Name (e.g., "Nescafe Original")
    *   Quantity Remaining (Text in red: "Only 2 left!")
    *   Action Button: "Restock" (Small button that routes to the manual inventory adjustment screen for this specific item).
*   **Logic:** The system queries the `inventory` table for items where `current_stock <= minimum_threshold`. The `minimum_threshold` defaults to 5 but is user-configurable per item.
*   **Empty State:** If all stock levels are healthy, this widget displays a green checkmark illustration with the text: "All stock levels look good!"

## 5.5 Widget 4: AI Suggestions & Insights (The Smart Feed)
*   **Position:** Below the Low Stock Alerts.
*   **Concept:** This widget replaces static, complex reporting with conversational, actionable AI-generated insights based on local data analysis.
*   **Visuals:** A card with a subtle glowing border or a distinct background color (e.g., light purple) to indicate "intelligence."
*   **Dynamic Content Examples:**
    *   *Pricing Insight:* "💡 You sold 50 Coke Mismos this week. Consider buying in larger bulk from your supplier to increase profit."
    *   *Demand Prediction:* "🌧️ It's rainy season. Based on last month's data, consider stocking up on instant noodles and coffee."
    *   *Stale Inventory Alert:* "⏳ You have 15 cans of Sardines that haven't sold in 3 weeks. Maybe move them to the front of the store?"
*   **Interaction:** Tapping the insight card provides more details or routes to the relevant inventory item.
*   **Offline AI Logic:** These insights are generated by local SQL aggregations run on a background thread during off-peak hours (e.g., when the app is opened but idle), utilizing hardcoded heuristics and simple statistical models.

## 5.6 Widget 5: Recent Transactions
*   **Position:** Bottom of the Dashboard ScrollView.
*   **Visuals:** A simple, concise list of the last 3 to 5 POS transactions.
*   **Content per Row:**
    *   Time (e.g., "10:14 AM")
    *   Transaction ID or Item Summary (e.g., "3 items")
    *   Total Amount (e.g., "₱ 120.00")
*   **Interaction:** Tapping a row opens a modal displaying the detailed digital receipt for that specific transaction (allowing for voiding or refunding if permitted).
*   **Header Action:** A "View All" text button next to the "Recent Transactions" header routes the user to the full Transaction History list.

## 5.7 The Floating Action Button (FAB)
*   **Position:** Anchored to the bottom right of the screen, sitting slightly above the Bottom Navigation Bar.
*   **Visuals:** A large circular button featuring a prominent Camera icon. It uses the app's primary accent color and casts a distinct drop shadow to draw attention.
*   **Functionality:** This is the most critical button in the application. It provides universal, one-tap access to the core feature: the AI Receipt Scanner. Regardless of how far the user has scrolled down the dashboard, this button remains fixed and accessible.

## 5.8 Edge Cases and Performance
*   **Massive Databases:** If the user has tens of thousands of transactions, running a `SUM()` query for the Daily Sales widget could block the UI thread. To prevent this, the architecture utilizes asynchronous isolates (Flutter) to run database queries in the background, rendering a skeleton loading state (shimmer effect) on the widget until the data is returned (usually <50ms on a local SQLite DB).
*   **First Launch (Empty State):** On the very first launch post-onboarding, the Dashboard detects that the `inventory` and `transactions` tables are empty. 
    *   The Financial Card shows ₱0.00.
    *   The Low Stock widget is hidden.
    *   The AI Suggestions widget is replaced with an onboarding tutorial card: "Ready to start? Tap the camera icon to scan your first receipt!"
    *   The Recent Transactions widget is hidden.
